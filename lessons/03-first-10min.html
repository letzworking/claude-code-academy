첫 10분 체험

  • ⏱ 10분
  • 🛠 실습
  • 🎯 미션 3개
이 레슨을 마치면
  • 내 코드에 대해 AI에게 질문하고 쓸모 있는 답을 받아 본 경험이 생깁니다.
  • "이거 생각보다 쓸 만한데?"라는 감각을 얻습니다.

준비는 하나입니다. 평소 작업하는 프로젝트 폴더에서 claude를 실행하세요. 아래 프롬프트의 { } 부분만 내 프로젝트에 맞게 바꾸면 됩니다.

💡

미션 1·2는 코드를 읽기만 합니다. 아무것도 바뀌지 않으니 마음 편히 시도하세요. 미션 3은 별도 브랜치에서 하는 걸 권합니다.

미션 1 · 오래된 코드 설명받기

아무도 설명해 주지 않던 클래스 하나를 골라 보세요. 길고 복잡할수록 효과가 큽니다.

프롬프트
{OrderService.java}가 하는 일을 설명해줘.
1) 한 문단 요약
2) 주요 메서드별 역할
3) 이 클래스를 수정할 때 조심해야 할 부분

확인할 것 — 설명이 내가 알던 내용과 맞나요? 혹시 몰랐던 의존 관계가 보이나요?

더 해보기: "이 메서드를 호출하는 곳을 모두 찾아줘", "이 흐름을 순서도처럼 단계별로 그려줘"

미션 2 · 숨은 문제 찾기

최근에 문제가 있었거나, 왠지 불안했던 코드를 골라 보세요.

프롬프트
{PaymentService.java}에서 잠재적인 버그나 위험한 부분을 찾아줘.
예: null 처리 누락, 예외 삼킴, 트랜잭션 범위, 동시성 문제.
심각한 순서로 정렬하고, 각 항목에 해당 줄 번호와 이유를 적어줘.
아직 코드는 수정하지 마.

확인할 것 — 지적이 모두 맞지는 않을 수 있습니다. 여러분의 판단으로 "맞다 / 아니다"를 가려 보세요. 그 과정 자체가 AI와 일하는 핵심입니다.

🗣

틀린 지적이 있으면 바로 말해 주세요. "3번은 상위에서 이미 검증하니까 문제없어"라고 하면 Claude가 맥락을 반영해 다시 판단합니다.

미션 3 · 작은 변경 맡겨보기

이제 처음으로 코드를 바꿔 봅니다. 위험이 낮은 "주석 달기"부터 시작합니다.

먼저 작업용 브랜치를 만드세요
git checkout -b try/claude-first
프롬프트
{OrderService.java}의 public 메서드에 Javadoc을 추가해줘.
- 메서드가 "왜" 존재하는지 위주로, 한국어로
- 코드 로직은 절대 바꾸지 마
- 끝나면 변경한 내용을 요약해줘

Claude가 수정 전에 확인을 요청하면 변경 내용을 읽어보고 승인하세요. 끝나면 직접 diff를 확인합니다.

변경 확인
git diff

마음에 들지 않으면 Esc 두 번(또는 /rewind)으로 되돌리거나, git checkout .으로 깨끗하게 원복하면 됩니다.

어떠셨나요?

세 미션을 하면서 아래 중 하나라도 느꼈다면 첫 단계는 성공입니다.
