잘 쓰는 습관

  • ⏱ 10분
  • 📖 읽기
이 레슨을 마치면
  • 결과가 좋아지는 요청 방법 다섯 가지를 압니다.
  • 팀 규칙을 한 번만 알려주면 계속 지키게 하는 방법(CLAUDE.md)을 압니다.

습관 1 · 신입에게 일을 맡기듯 요청하기

좋은 요청은 우리가 신입 개발자에게 업무를 줄 때와 똑같습니다. 배경, 대상, 완료 조건을 알려주세요.

😕 막연한 요청

"로그인 고쳐줘"

🙂 구체적인 요청

"비밀번호 5회 오류 시 계정이 잠겨야 하는데 안 잠겨. LoginService를 확인해서 원인을 찾고, 재현 테스트를 만든 다음 고쳐줘."

😕 범위가 열린 요청

"코드 좀 개선해줘"

🙂 범위가 정해진 요청

"ProductService의 중복된 가격 계산 로직만 하나로 합쳐줘. 다른 클래스는 건드리지 말고."

습관 2 · 큰 작업은 계획부터 (Plan 모드)

여러 파일을 고치는 작업이라면 바로 시키지 말고 Shift+Tab으로 Plan 모드로 바꾸세요. Claude는 코드를 고치지 않고 조사한 뒤 계획만 보여줍니다. 계획을 검토하고 고칠 점을 말한 다음 승인하면 실행이 시작됩니다.

💡

설계 리뷰를 해본 경험이 바로 여기서 빛납니다. 계획 단계에서 잡은 문제 하나가 나중의 수정 열 개를 줄여줍니다.

습관 3 · 팀 규칙은 CLAUDE.md에 한 번만

매번 "우리는 Lombok 써", "테스트는 Gradle로 돌려"라고 말하기 번거롭죠. 프로젝트 루트에 CLAUDE.md 파일을 두면 Claude가 세션을 시작할 때마다 자동으로 읽습니다. /init을 입력하면 프로젝트를 분석해 초안을 만들어 줍니다.

CLAUDE.md 예시
# 주문 서비스

## 빌드·테스트
- 빌드: ./gradlew build
- 테스트: ./gradlew test

## 코딩 규칙
- Java 17, Spring Boot 3, MyBatis
- DTO는 record 사용, 엔티티에는 Lombok @Getter만 허용
- 테스트는 JUnit 5 + Mockito, @DisplayName은 한국어로

## 주의
- order_hist 테이블은 새벽 배치가 사용하므로 스키마 변경 금지
- application-prod.yml은 절대 수정하지 말 것

팀 저장소에 커밋해 두면 팀원 모두가 같은 규칙으로 Claude를 쓰게 됩니다. 나만 쓰는 설정은 CLAUDE.local.md에 두면 됩니다.

습관 4 · 결과는 반드시 확인하기

  • 테스트로 검증 — "테스트 돌려서 통과시켜줘"를 요청 끝에 붙이는 습관
  • diff 직접 읽기 — 커밋 전에 git diff나 IDE diff로 한 번은 눈으로 확인
  • 왜 그렇게 했는지 묻기 — "이 부분은 왜 이렇게 바꿨어?"라고 물으면 근거를 설명합니다

습관 5 · 대화가 길어지면 새로 시작

한 대화에서 여러 주제를 오가면 앞의 내용이 뒤섞여 답의 질이 떨어질 수 있습니다. 주제가 바뀌면 /clear로 새로 시작하세요. 이어서 해야 하는데 대화가 너무 길면 /compact로 요약해 정리할 수 있습니다.

이것만은 하지 마세요

🚫
  • 비밀번호·API 키·운영 DB 접속 정보를 프롬프트에 붙여넣기
  • 고객 개인정보가 담긴 로그·데이터를 그대로 붙여넣기
  • 운영 서버나 운영 DB에 직접 연결된 환경에서 무작정 실행하기
  • 내용을 읽지 않고 모든 승인 요청에 "허용" 누르기
  • 이해하지 못한 코드를 그대로 커밋하기
