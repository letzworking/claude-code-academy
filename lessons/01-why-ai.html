로드맵 / 레슨 01

왜 지금 AI인가

  • ⏱ 5분
  • 📖 읽기
이 레슨을 마치면
  • Claude Code가 "똑똑한 자동완성"과 어떻게 다른지 설명할 수 있습니다.
  • AI에게 무엇을 맡기고 무엇을 내가 해야 하는지 감이 잡힙니다.

자동완성이 아니라 "일을 맡길 수 있는 동료"

IDE의 코드 자동완성은 커서 앞의 몇 줄을 예측해 줍니다. 편리하지만 결국 타이핑을 줄여주는 도구입니다.

Claude Code는 다릅니다. 터미널에서 실행되는 AI 에이전트로, 여러분이 목표를 말하면 스스로 파일을 찾아 읽고, 코드를 수정하고, 빌드·테스트 명령을 실행하고, 그 결과를 보고 다시 고칩니다.

코드 자동완성Claude Code
입력지금 쓰고 있는 코드"이 버그 원인 찾아줘" 같은 목표
보는 범위열려 있는 파일 주변프로젝트 전체 (필요한 파일을 스스로 찾음)
할 수 있는 일다음 줄 제안읽기 · 수정 · 명령 실행 · 테스트 · 커밋
내 역할타이핑방향 제시 · 검토 · 최종 결정

한 번의 요청이 처리되는 모습

Claude Code는 아래 흐름을 반복합니다. 중요한 점은 시작과 끝에 항상 여러분이 있다는 것입니다.

나① 목표 설명"주문 취소 시 재고 복구가 안 돼. 원인 찾아줘."
AI② 조사관련 파일을 찾아 읽고 호출 흐름을 추적
AI③ 실행수정안을 만들고 테스트를 돌려 확인
나④ 검토·결정변경 내용을 보고 승인하거나 방향 수정

시니어의 경험이 오히려 강점인 이유

AI를 비유하자면 엄청나게 빠르고 지치지 않지만, 우리 회사 사정은 모르는 유능한 신입입니다. 코드는 빨리 쓰지만 "이 테이블은 배치가 새벽에 잠가서 건드리면 안 돼" 같은 맥락은 모릅니다.

그래서 AI를 잘 쓰는 사람은 프롬프트 기술이 좋은 사람이 아니라 다음을 잘하는 사람입니다.

🎯 무엇을 시킬지 아는 것

문제를 적절한 크기로 쪼개고, 무엇이 중요한지 짚어주는 능력

🔍 결과를 판단하는 것

그럴듯해 보이는 코드에서 잘못된 가정과 위험을 찾아내는 눈

🧭 맥락을 알려주는 것

팀 컨벤션, 운영 환경 제약, 과거 장애 이력 같은 도메인 지식

✅ 기준을 세우는 것

"테스트 통과", "기존 API 호환" 같은 완료 조건을 정하는 감각

모두 여러분이 수년간 쌓아온 능력입니다. 새로 배울 것은 생각보다 적습니다.

자주 받는 걱정

회사 코드를 넣어도 괜찮을까요?

공식 문서에 따르면 Team·Enterprise·API 같은 상업용 약관으로 사용할 때는 기본적으로 코드나 프롬프트를 모델 학습에 사용하지 않습니다. 개인 요금제는 학습 활용 여부를 설정에서 직접 선택할 수 있습니다.

다만 이건 출발점일 뿐입니다. 회사의 AI 사용 정책과 보안팀 가이드를 먼저 확인하세요. 자세한 내용: 데이터 사용 정책 (공식 문서)

AI가 틀린 코드를 만들면요?

틀릴 수 있습니다. 그래서 검토는 여러분의 몫입니다. 다행히 Claude Code는 테스트를 직접 실행해 결과를 확인할 수 있고, 변경 전 상태로 되돌리는 기능(Esc 두 번 또는 /rewind)도 있습니다. "테스트를 먼저 만들고 통과시켜줘"라고 요청하는 습관이 가장 좋은 안전장치입니다.

제 일자리를 위협하는 것 아닌가요?

AI가 가장 약한 부분은 바로 시니어가 가장 강한 부분, 즉 판단과 맥락입니다. 반복적인 코드 작성은 AI에게 넘기고, 설계·리뷰·의사결정에 시간을 더 쓰는 쪽이 경력을 더 단단하게 만듭니다.

나이 들어서 새로운 도구 익히기가 부담돼요.

Claude Code의 사용법 대부분은 "한국어로 요청하기"입니다. 외울 명령어는 다섯 개 남짓이고, 그것도 치트시트 한 장에 정리해 두었습니다. 모르면 Claude에게 "이건 어떻게 해?"라고 물어보면 됩니다.

한 줄 요약 — AI는 손이 빠른 동료이고, 여러분은 그 동료를 이끄는 리드입니다.
